        怎么读这两组预设

        系统 Intent 用的是平台标准 action（android.settings.*、 action.DIAL、geo: …），任何设备都有应用应答， 而且「哪个应用来处理」完全是系统决定的。 第三方 App 用的是各 App 自己注册的自定义 scheme，属于约定俗成的值： 同一个 App 换个版本就可能改名或收紧，只当测试起点用。 两组都不指定 package，交给系统解析。

        URI 结构

        intent://<host><path>?<query>#Intent;scheme=…;action=…;category=…;S.key=value;end

        #Intent; 之前的部分是 App 最终收到的 data。 Android 的还原规则是 data = scheme + ":" + 去掉 intent: 之后的原文， 所以 intent://dl/nav 配 scheme=weixin 得到 weixin://dl/nav； 而 intent:10086 配 scheme=smsto 得到 smsto:10086（没有 //）。 这一点最容易写错：像 tel:、smsto:、 mailto: 这类 opaque URI 必须写成 intent:号码#Intent;…，多写两个斜杠就变成另一个 URI 了。

        参数表

        键含义
        scheme=设置 data 的 scheme，和左侧数据部分拼成完整 URI
        action=Intent action
        category=可重复出现，每写一次加一个 category
        type=MIME type，例如 text/plain（斜杠不会被转义）
        package=定向到某个包；不写则由系统解析
        component=显式组件 包名/类名；浏览器会清掉它
        launchFlags=启动 flag，十进制或 0x…
        end参数段结束标记，最后一个分号之后必须是它

        extras 前缀（大小写敏感）：

        前缀Bundle 类型值怎么写
        S.String任意文本，按 UTF-8 百分号编码
        i.int整数
        l.long整数
        s.short整数，-32768…32767
        B.booleantrue / false
        b.byte整数，-128…127
        f.float小数
        d.double小数
        c.char单个字符

        注意 B. 是布尔、b. 是字节 —— 顺序和很多博客写的相反，以 Android 源码里的 Intent.parseUri 为准。

        浏览器会在什么情况下拒绝唤起

        链接本身没问题、但点了没反应，绝大多数是下面几条（整理自 Chrome 的 external_intents 说明与 Android Intents with Chrome 文档）：

        不是用户手势触发必须由真实点击/触摸发起。定时器、自动跳转、页面加载时触发都会被拦。
        指定的 Intent 解析不到应用没有任何应用能处理 → 无反应。可以用 S.browser_fallback_url 兜底。
        显式 Intent（指定 component）Chrome 在解析时调用 setComponent(null)，显式组件会被丢掉。
        缺少 BROWSABLE category浏览器只会唤起声明了 BROWSABLE 的 Activity；Chrome 也会自己补上这个 category。
        链接是从别的 URL 重定向来的重定向链路上的 intent 不会被唤起（防滥用）。
        浏览器自己就能处理的 schemehttp/https 若 App 没有已验证的 App Link，浏览器会自己打开网页，不交给 App。
        同一个用户手势里重复唤起会被当成指纹探测而拦截，所以不要在一次点击里连发多个链接。
        file: / content: 等 scheme属于受限 scheme，是否放行看浏览器版本。
        在 App 内置浏览器里微信、QQ、微博等内置 WebView 通常直接屏蔽外部 App 唤起，请换 Chrome 打开。

        排错速查

        现象多半是
        点了完全没反应目标 App 没装，或者没有应用注册这个 scheme。先用系统 Intent 预设确认页面本身是通的。
        跳到了浏览器但没进 Apphttp/https 目标且 App 未通过 App Link 验证。换成 App 的自定义 scheme，或加上 package=。
        弹出了应用选择框多个应用都能处理。想指定就用 package=。
        进了 App 但停在了首页scheme 只匹配到了首页入口，具体页面需要正确的 host/path，或改用 App 提供的 deep link。
        微信/QQ 里打不开内置浏览器屏蔽了唤起。右上角「在浏览器打开」后再试。
        唤起成功但读不到 extras数据类型不对。检查 B./b. 有没有写反，数字类型有没有混进非数字。

        在手机上打开本页

        唤起只能由 Android 设备上的浏览器完成，桌面浏览器点了不会有反应。 本页是纯静态文件，把目录交给任意 HTTP 服务即可：

        1. 在仓库目录执行 python -m http.server 8000（或任意静态服务器）
        2. 查看电脑局域网 IP，例如 Windows 上 ipconfig、macOS/Linux 上 ipconfig getifaddr en0 / hostname -I
        3. 手机与电脑连同一个 Wi-Fi，用 Chrome 打开 http://<你的IP>:8000/
        4. 或者直接点页面里的「二维码」，用手机扫码把当前链接带过去

        也可以直接把 index.html 拷到手机上用文件管理器打开，但那样就没有同源限制之外的额外好处， 建议还是走 HTTP。电话/短信这类系统 Intent 需要设备上有可应答的应用。
